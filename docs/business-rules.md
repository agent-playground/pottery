# pottery 業務規則（核心模組）

> 本文件由人類在 S7 撰寫（工廠只負責把流程帶到這裡）。範圍是 `pottery/` 的核心行為；
> 每條規則都對應可觀察的行為，測試（S8）與驗證閘門（S10）以它為判準。

## 1. Redlock（分布式鎖）

| 規則 | 可觀察行為 |
|---|---|
| R1 取得鎖需在過半數節點成功 | 當 `quorum = n//2 + 1` 時，成功節點數 < quorum 必須回 `False`，且已取得的節點要釋放 |
| R2 鎖的有效期限是絕對的 | 超過 `expire` 後，即使原持有者未釋放，其他客戶端也可取得 |
| R3 只有持有者可釋放 | 非持有者（不同的 token／已過期）呼叫釋放不得刪除他人的鎖 |
| R4 重試有上限與退避 | `retry_count` / `retry_delay` 內取不到鎖回 `False`，不無限迴圈 |

## 2. NextId（單調遞增 ID）

| 規則 | 可觀察行為 |
|---|---|
| R5 同一 key 的 ID 嚴格遞增 | 連續呼叫回傳值必為遞增序列，且不重複 |
| R6 併發下不重複 | 多執行緒／多行程同時取號，回傳值集合無重複 |
| R7 號段可設定 | `initial_value` / `chunk_size` 生效，且不會回退到已配發過的號碼 |

## 3. Redis 型別（collections）

| 規則 | 可觀察行為 |
|---|---|
| R8 型別操作與原生 Redis 語意一致 | `Dict`／`Set`／`List` 的邊界行為（空集合、不存在 key、覆寫）與 Redis 指令一致 |
| R9 序列化可逆 | 寫入後讀出的值與寫入前相等（含 bytes／str 邊界） |
| R10 TTL 可套用 | 設定 `expire` 後，逾時即消失，不留下孤兒 key |

## 4. 連線與錯誤處理

| 規則 | 可觀察行為 |
|---|---|
| R11 連線失敗要明確報錯 | Redis 不可用時拋出可辨識的錯誤，不靜默回 `None` |
| R12 pipeline／transaction 失敗要整體回滾 | 交易中一項失敗，其他項不得部分生效 |

## 5. 不對外承諾

- 不保證跨 Redis 叢集的鎖公平性（Redlock 的既有理論限制）。
- 不代管 Redis 的 ACL／認證設定（見 `catalog-info.yaml` 的風險註記）。
